# XenServer ISO Builder

Type: `xenserver-vm-iso`

Artifact BuilderId: `packer.xenserver`

The `xenserver-vm-iso` builder creates a new virtual machine on a XenServer pool from an
installation ISO. It boots the installer, lets an `Autounattend.xml` answer file drive the
installation, provisions the guest over WinRM, and exports the result.

- XenCenter is not required: the builder uses the XenAPI.
- Tested against **XenServer 9**. Earlier versions are not supported.
- This release supports Windows guests, connected to over WinRM.

## Examples

### Windows (autounattend, from an ISO already on an SR)

This example installs Windows 11 from an ISO already on an ISO SR, delivers
`Autounattend.xml` on a CD via `cd_files`, and connects over WinRM. Credentials come from
Packer input variables.

```hcl
packer {
  required_version = ">= 1.7.0"

  required_plugins {
    xenserver = {
      source  = "github.com/xenserver/xenserver"
      version = ">= 1.0.0"
    }
  }
}

variable "xenserver_host" {
  type = string
}
variable "xenserver_password" {
  type      = string
  sensitive = true
}
variable "winrm_password" {
  type      = string
  sensitive = true
}

source "xenserver-vm-iso" "windows" {
  # --- Connection ---
  xenserver_host     = var.xenserver_host
  xenserver_username = "root"
  xenserver_password = var.xenserver_password
  ca_cert_path       = "pool-ca.pem"

  # --- Installation media already staged on an ISO SR ---
  iso_name = "Win11.iso"
  iso_sr   = "ISO library"

  # --- VM hardware ---
  vm_name        = "packer-windows11"
  vcpus          = 4
  vm_memory_gb   = 8
  disk_size_gb   = 64
  firmware       = "uefi"
  secure_boot    = true
  vtpm           = true
  network_names  = ["Pool-wide network associated with eth0"]
  clone_template = "Windows 11"

  # --- Answer file and VM Tools MSI on a CD ---
  cd_files  = ["autounattend/Autounattend.xml", "autounattend/managementagentx64.msi"]
  boot_wait = "3s"

  # Answers "Press any key to boot from CD"; a UEFI build repeats it on its own.
  boot_command = ["<enter>"]

  # --- Communicator: WinRM ---
  # The guest's 5986 listener presents a certificate the machine running Packer
  # trusts, issued for the address Packer connects to (see Windows Remote
  # Management below).
  communicator   = "winrm"
  winrm_username = "Administrator"
  winrm_password = var.winrm_password
  winrm_use_ssl  = true
  winrm_timeout  = "45m"

  # --- Output ---
  format           = "xva"
  output_directory = "output-windows11"
}

build {
  sources = ["source.xenserver-vm-iso.windows"]

  provisioner "powershell" {
    inline = ["Write-Host 'provisioned by packer'"]
  }
}
```

You supply `Autounattend.xml` and the VM Tools MSI; this repository ships neither. For this
build the answer file must:

- install the XenServer VM Tools from the MSI on the CD, since the build learns the VM's
  address from them;
- create the WinRM HTTPS listener on 5986, with a certificate that the machine running
  Packer trusts, issued for the address Packer connects to (see
  [Windows Remote Management](#windows-remote-management-winrm)).

With `communicator = "none"` the build does not connect, so no listener is needed, and the
answer file must shut the VM down at the end instead. See Microsoft's
[Unattended Windows Setup Reference](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/)
for how to write an answer file.

### ISO

Name the installation ISO one of two ways — by URL, or by the name of an ISO already on an
ISO SR. Set exactly one.

**By URL** — Packer downloads the ISO, checks it against `iso_checksum`, and uploads it to
`vm_sr` (see [Storage](#storage-sr)):

- `iso_url` (string) - URL of the installation ISO to download. Set this or `iso_urls`,
  not both.

- `iso_urls` ([]string) - Several URLs for the same ISO, tried in order until one
  downloads.

- `iso_checksum` (string) - **Required with a URL.** The ISO's checksum with its algorithm
  as a prefix, such as `sha256:<hash>` (`md5`, `sha1` and `sha512` work too); a bare hash,
  whose algorithm is inferred from its length; `file:<path or URL>` to read it from a
  checksum file; or `none` to skip the check, with a warning.

- `iso_target_path` (string) - Where to save the downloaded ISO. Defaults to Packer's
  cache.

- `iso_target_extension` (string) - File extension of the downloaded ISO. Defaults to
  `iso`.

**By name** — the ISO is already on `iso_sr`, and nothing is downloaded:

- `iso_name` (string) - Name label of the ISO on `iso_sr`.

- `guest_tools_iso` (string) - Deprecated, and not supported on XenServer 9, which ships no
  guest-tools ISO. Leave it unset.

### Storage (SR)

- `vm_sr` (string) - Name label of the SR for the VM's disk, the `cd_files` CD and a
  downloaded ISO, so it must be writable. Defaults to the pool's default SR. The name must
  be unique on the pool.

- `iso_sr` (string) - Name label of the SR that holds the ISO named by `iso_name`.
  **Required with `iso_name`.** It is only read, so a read-only ISO library works.

### Hardware / VM

- `clone_template` (string, **Required**) - Name label of the XenServer template the VM is
  cloned from, such as `Windows 11`. The VM takes the template's firmware, Secure Boot,
  vTPM and sizing unless the build sets them. Name `Other install media` to define the
  hardware yourself; `vcpus`, `vm_memory_gb` and `disk_size_gb` are then required. The name
  must match exactly one template; `xe template-list params=name-label` lists them.

- `vm_name` (string) - Name of the new VM. Defaults to `packer-BUILDNAME-TIMESTAMP`.

- `vm_description` (string) - Description of the new VM. Defaults to empty.

- `vcpus` (integer) - Number of virtual CPUs. Defaults to `clone_template`'s.

- `cores_per_socket` (integer) - Cores per socket. Must divide `vcpus`, giving at most 16
  sockets. Defaults to `clone_template`'s, and is ignored unless `vcpus` is set too.

- `vm_memory_gb` (integer) - Memory in GiB, as a fixed allocation with no ballooning.
  Defaults to `clone_template`'s.

- `disk_size_gb` (integer) - Size of the system disk in GiB. Defaults to
  `clone_template`'s.

> Windows 11 needs at least 2 vCPUs, 4 GB of memory and a 64 GB disk; Windows Server needs
> 2 GB of memory and a 32 GB disk. With too little memory, Windows Setup stalls instead of
> failing, and the build fails only when `install_timeout` expires.

- `firmware` (string) - `bios` or `uefi`. Defaults to `clone_template`'s firmware. The
  build fails early, before the ISO is downloaded, if the template cannot boot that way —
  for example `bios` with a template set up with a vTPM, as `Windows 11` is.

- `secure_boot` (bool) - Enable UEFI Secure Boot. `true` requires `firmware = "uefi"`, set
  explicitly. Defaults to `clone_template`'s setting. On a pool with no UEFI certificates
  installed, the VM starts with Secure Boot off.

- `vtpm` (bool) - Attach a virtual TPM. Requires `firmware = "uefi"`, set explicitly.
  Defaults to `false`, which adds none but keeps any vTPM setup `clone_template` has.

- `has_vendor_device` (bool) - Give the VM the device through which Windows Update offers
  the XenServer PV drivers. Windows needs it for a clean shutdown, reboot and suspend.
  Defaults to `true`.

- `vgpu_profile` (string) - vGPU profile to attach, matched as a case-insensitive substring
  of the pool's vGPU type names: `t4-2q` selects `GRID T4-2Q`. The build fails if no type
  matches. Defaults to none. See the
  [NVIDIA vGPU documentation](https://docs.nvidia.com/grid/latest/grid-vgpu-user-guide/index.html).

- `network_names` (array of strings) - Networks to attach, by name label, in order. They
  replace the networks `clone_template` has, and each name must match exactly one network.
  Defaults to `clone_template`'s networks, or the management network if it has none.

- `vm_other_config` (map of string→string) - Key/value pairs added to the VM's
  `other-config`. Defaults to empty. Two keys are reserved; see
  [Build Provenance](#build-provenance).

### HTTP

Packer can serve a directory over HTTP for the installer to fetch files from. The VM must
be able to reach it.

- `http_directory` (string) - Directory to serve. Defaults to none. Its address and port
  are available to `boot_command` as `.HTTPIP` and `.HTTPPort`; the port is picked from
  8000–9000.

- `http_bind_address` (string) - IP address the server binds to, also handed to the guest
  as `.HTTPIP`. Defaults to every interface, with `.HTTPIP` taken from the route to
  `xenserver_host`. Set it when the guest reaches the machine running Packer on a
  different network from the pool.

- `http_interface` (string) - Network interface whose IPv4 address is handed to the guest
  as `.HTTPIP`. Use it instead of `http_bind_address`, not with it.

### CD-ROM

- `cd_files` (array of strings) - Files and directories to put on a CD attached at boot,
  such as `Autounattend.xml`. Works under BIOS and UEFI. Wildcards are not expanded.
  Building the CD needs `xorriso`, `mkisofs`, `hdiutil` or `oscdimg` on the machine
  running Packer. Defaults to none.

### Boot

- `boot_command` (array of strings) - Keys typed over VNC to start the installer; see
  [Boot Command](#boot-command). Defaults to none.

- `boot_wait` (string) - How long to wait after power-on before typing `boot_command`.
  Defaults to `5s`.

- `boot_key_groups` (integer) - How many times to send `boot_command`,
  `boot_key_group_interval` apart, to catch a prompt whose timing varies, such as UEFI's
  "Press any key to boot from CD". Defaults to 20 on a UEFI VM whose `boot_command` is a
  single `<enter>`, `<return>` or `<spacebar>`, and to 1 otherwise. Use `<enter>` for
  Windows.

- `boot_key_group_interval` (string) - Time between those repetitions. **Required when
  `boot_key_groups` is above 1.** Defaults to `1s` with the UEFI default above.

### Communicator Configuration

Packer connects to the guest over WinRM to run provisioners. A build that provisions the
guest sets `communicator = "winrm"`, with `winrm_username` and `winrm_password`.

With `communicator = "none"`, the default, Packer cannot connect to the VM or run anything
inside it, so the build only waits for the VM to shut down and then exports it. Shut the
VM down from the answer file or by hand; otherwise the build fails when `install_timeout`
expires.

#### Common

- `communicator` (string) - `none` (the default) or `winrm`.

- `pause_before_connecting` (duration string | ex: "1h5m2s") - How long to wait, once
  WinRM is reachable, before provisioning starts. Use it when WinRM comes up before the
  guest has finished its own setup. Defaults to no pause.

#### Windows Remote Management (WinRM)

Packer must be able to reach the VM on its network, and the guest must already be
listening. With `winrm_use_ssl = true` that means an HTTPS listener on 5986, which a fresh
Windows install does not have: create it from the answer file's `FirstLogonCommands`, with
a certificate that the machine running Packer trusts, issued for the address Packer
connects to (for example, imported from a PFX staged with `cd_files`). With the
certificate in the machine store:

```powershell
Enable-PSRemoting -Force
New-Item -Path WSMan:\localhost\Listener -Transport HTTPS -Address * -CertificateThumbPrint '<thumbprint>' -Force
Set-Item WSMan:\localhost\Service\Auth\Basic -Value $true
netsh advfirewall firewall add rule name='WinRM HTTPS 5986' dir=in action=allow protocol=TCP localport=5986
```

Leave `winrm_insecure` at its default, `false`, so that Packer verifies the certificate. Do
not open 5985 with `AllowUnencrypted` instead: the credentials would cross the network in
clear text.

### Output & Export

- `format` (string) - What the build produces:

  | Value            | Result                                                                    |
  | ---------------- | ------------------------------------------------------------------------- |
  | `xva`            | A gzip-compressed XVA file, `<vm_name>.xva`. The default.                 |
  | `xva_compressed` | Deprecated alias of `xva`.                                                |
  | `vdi_raw`        | One raw image per disk, `<vdi-uuid>.raw`.                                 |
  | `vdi_vhd`        | One VHD image per disk, `<vdi-uuid>.vhd`. Disks over 2040 GiB cannot be exported this way. |
  | `none`           | No file: the finished VM is converted to a template and left on the pool. |

- `output_directory` (string) - Directory for the exported files. Defaults to
  `output-BUILDNAME`. It must be missing or empty; `packer build -force` empties it first.
  `-force` also destroys any VM or template on the pool named `vm_name`, with its disks.

- `keep_vm` (string) - When to keep the VM on the pool: `never`, `always` or
  `on_success`. Defaults to `on_success` with `format = "none"`, and to `never` otherwise;
  `never` with `format = "none"` is rejected. Use `always` to keep the VM of a failed build
  for debugging.

- `create_snapshot` (bool) - Snapshot the VM after it shuts down, before it is exported.
  Defaults to `false`. The build never deletes the snapshot, even with
  `keep_vm = "never"`.

- `snapshot_name` (string) - Name label of that snapshot. Only valid with
  `create_snapshot = true`.

### Advanced

- `install_timeout` (string) - How long to wait for the installation to finish: with
  `winrm`, until the VM reports an address; with `none`, until the VM shuts down. Defaults
  to `200m`.

- `shutdown_command` (string) - Command run inside the guest over WinRM to shut it down
  after provisioning; it needs `communicator = "winrm"`. Without it, the VM is shut down
  through the XenAPI. If the VM has not halted within five minutes, it is powered off.

## Boot Command

`boot_command` is typed over **VNC**, as if at the keyboard, once `boot_wait` has passed.
The strings are typed in order. These special keys are recognized:

- `<bs>` — Backspace
- `<del>` — Delete
- `<enter>` / `<return>` — Enter/Return
- `<esc>` — Escape
- `<tab>` — Tab
- `<f1>`–`<f12>` — Function keys
- `<up>` `<down>` `<left>` `<right>` — Arrow keys
- `<spacebar>` — Spacebar
- `<insert>` — Insert
- `<home>` `<end>` — Home / End
- `<pageUp>` `<pageDown>` — Page Up / Page Down
- `<wait>` — Pause one second before the next keys
- `<waitN>` — Pause for N seconds, for example `<wait5>`. Other durations also work:
  `<wait500ms>`, `<wait2m>`, `<wait1m30s>`

Anything else is typed as it is. Keep to Latin-1 characters, and use `<enter>` and `<tab>`
rather than literal newlines or tabs.

Each string is also a template, with these variables:

- `.Name` — the name of the VM being built.
- `.HTTPIP` and `.HTTPPort` — the address and port of Packer's HTTP server (see
  [HTTP](#http)). Without `http_directory`, `.HTTPPort` is `0`.

## Troubleshooting

- **The build waits for the guest and fails with no IP address** — the address comes from
  the XenServer VM Tools in the guest, or from the guest fetching a file from Packer's HTTP
  server. Check that the guest got a DHCP lease, and that the tools are installed (keep
  `has_vendor_device` on) or the guest can reach the HTTP server.

- **A `communicator = "none"` build fails after `install_timeout`** — the build exports
  only once the VM has shut down. Shut it down at the end of the answer file
  (`shutdown /s`), or by hand.

- **Windows Setup stalls** — check `vm_memory_gb` against the minimum: 4 GB for Windows 11,
  2 GB for Windows Server. Set `keep_vm = "always"` to inspect the VM afterwards.

- **The installer boots to a UEFI shell, or stops at Windows Boot Manager** — the "Press any
  key to boot from CD" prompt was missed. Use `boot_command = ["<enter>"]`, which a UEFI
  build repeats on its own; for any other boot command, set `boot_key_groups` and
  `boot_key_group_interval`.

- **`ca_cert_path must be specified when insecure is false`** — export the pool's
  certificate with `xe host-get-server-certificate host=<host-uuid> > pool-ca.pem` and
  point `ca_cert_path` (or `XENSERVER_CA_CERT_PATH`) at it.

- **`certificate is valid for X, not Y`** — connect with a name or address the pool's
  certificate is issued for.

- **`HOST_IS_SLAVE`** — point `xenserver_host` at the pool coordinator (master).

- **WinRM never connects** — check that the guest's HTTPS listener is up on 5986, the
  firewall allows it, the credentials are right, and the listener's certificate is trusted
  by the machine running Packer and issued for the address Packer connects to.

- **`<option> must be specified with clone_template 'Other install media'`** — that
  template carries no sizing. Set the options the message names, or name the template for
  the guest OS.

- **An error about `firmware` and the template's boot mode or vTPM** — remove `firmware` to
  keep the template's own, or name a template that boots the way you need.

- **`SR_BACKEND_FAILURE_78 ... VDI Creation failed`** — the SR the build uploads to is
  read-only. Point `vm_sr` at a writable SR.

- **`Couldn't find a VDI named '...' in SR '...'`** — the ISO named by `iso_name` is not on
  `iso_sr`.

## Required Privileges (RBAC)

The account in `xenserver_username` needs at least the **Pool Operator** role; `root`
(Pool Admin) always works. See
[role-based access control](https://docs.xenserver.com/en-us/xenserver/9/users/rbac-overview.html).
