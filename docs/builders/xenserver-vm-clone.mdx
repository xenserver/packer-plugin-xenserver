# XenServer Clone Builder

Type: `xenserver-vm-clone`

Artifact BuilderId: `packer.xenserver`

The `xenserver-vm-clone` builder clones an existing XenServer **template** or **VM**, boots
it, provisions it over WinRM, and exports the result or leaves it on the pool as a
template. Use it to update an existing image, such as a sysprepped Windows template,
without reinstalling. To build from an installation ISO instead, see the
[`xenserver-vm-iso`](/packer/integrations/xenserver/xenserver/latest/components/builder/xenserver-vm-iso)
builder.

- XenCenter is not required: the builder uses the XenAPI.
- Tested against **XenServer 9**. Earlier versions are not supported.
- This release supports Windows guests, connected to over WinRM.

## Examples

This example clones a Windows template, provisions it over WinRM, and leaves the result on
the pool as a template. Credentials come from Packer input variables. A complete version is
in [`examples/windows-clone-winrm`](https://github.com/xenserver/packer-plugin-xenserver/tree/main/examples/windows-clone-winrm)
in the repository.

```hcl
packer {
  required_version = ">= 1.7.0"

  required_plugins {
    xenserver = {
      version = ">= 1.0.0"
      source  = "github.com/xenserver/xenserver"
    }
  }
}

variable "xenserver_host" {
  type = string
}

variable "xenserver_username" {
  type    = string
  default = "root"
}

variable "xenserver_password" {
  type      = string
  sensitive = true
}

variable "winrm_username" {
  type    = string
  default = "Administrator"
}

variable "winrm_password" {
  type      = string
  sensitive = true
}

source "xenserver-vm-clone" "windows" {
  # Connection to the pool coordinator
  xenserver_host     = var.xenserver_host
  xenserver_username = var.xenserver_username
  xenserver_password = var.xenserver_password
  ca_cert_path       = "pool-ca.pem"

  # Source and networks. The source must already have the XenServer VM Tools
  # installed: the build learns the VM's address from them.
  clone_template = "Windows 11 (64-bit) golden"
  network_names  = ["Pool-wide network associated with eth0"]

  # Hardware
  vm_name      = "packer-win11-golden"
  vm_memory_gb = 8
  vcpus        = 4

  # Communicator: WinRM. The source's 5986 listener presents a certificate the
  # machine running Packer trusts, issued for the address Packer connects to.
  communicator   = "winrm"
  winrm_username = var.winrm_username
  winrm_password = var.winrm_password
  winrm_use_ssl  = true
  winrm_timeout  = "30m"

  # Output: leave a template on the pool instead of exporting a file
  format = "none"
}

build {
  sources = ["source.xenserver-vm-clone.windows"]

  provisioner "powershell" {
    inline = [
      "Write-Host 'Provisioning the golden image...'",
      "Get-Service -Name WinRM | Format-List Name, Status"
    ]
  }
}
```

## Configuration Reference

Exactly one of `clone_template` and `clone_vm` is required, along with the
[connection](#connection) settings. Every other option is optional, and most default to
the source's value.

### Clone Configuration

**Required — exactly one of:**

- `clone_template` (string) - Name label of the template to clone. It must match exactly
  one template on the pool.

- `clone_vm` (string) - Name label of the VM or snapshot to clone. It must match exactly
  one VM or snapshot on the pool. A VM must be halted; to build from a running VM, snapshot
  it and name the snapshot, which gives an image crash-consistent as of the snapshot. A
  checkpoint (a snapshot that includes memory) cannot be combined with `vm_sr`.

**Optional — placement:**

- `vm_sr` (string) - Name label of the SR for the clone's disks. Defaults to the source's
  SR. Naming another SR copies the disks in full rather than cloning them, which takes as
  long as writing that much data.

- `network_names` (array of strings) - Networks to attach, by name label, in order. They
  replace the source's networks, and each name must match exactly one network. Defaults to
  the source's networks, or the management network if it has none.

**Optional — hardware:**

- `vm_name` (string) - Name of the new VM. Defaults to `packer-BUILDNAME-TIMESTAMP`.

- `vm_description` (string) - Description of the new VM. Defaults to empty.

- `vm_memory_gb` (integer) - Memory in GiB, as a fixed allocation with no ballooning.
  Defaults to the source's.

- `vcpus` (integer) - Number of virtual CPUs. Defaults to the source's.

- `cores_per_socket` (integer) - Cores per socket. Must divide `vcpus`, giving at most 16
  sockets. Defaults to the source's, and is ignored unless `vcpus` is set too.

- `disk_size_gb` (integer) - Size of the primary disk in GiB. The disk can only grow: a
  size below the source's fails the build. Only the virtual disk is resized, so extend the
  partition and filesystem from a provisioner. Defaults to the source's size.

- `firmware` (string) - `bios` or `uefi`. Defaults to the source's firmware. The build
  fails before anything is cloned if the source cannot boot that way — for example `bios`
  with a source that has run under UEFI or has a vTPM.

- `secure_boot` (bool) - Enable UEFI Secure Boot. `true` requires `firmware = "uefi"`, set
  explicitly; `false` turns Secure Boot off. Defaults to the source's setting. On a pool
  with no UEFI certificates installed, the VM starts with Secure Boot off.

- `vtpm` (bool) - Attach a virtual TPM. Defaults to the source's: unset keeps whatever it
  has. `true` adds one, and requires `firmware = "uefi"`, set explicitly. `false` removes
  the inherited vTPM and **cannot be undone**: anything sealed to it, such as a BitLocker
  key, is lost in the built image. The source keeps its own vTPM.

- `has_vendor_device` (bool) - Give the VM the device through which Windows Update offers
  the XenServer PV drivers. Windows needs it for a clean shutdown, reboot and suspend.
  Defaults to the source's setting. **Changing it on a source that already has Windows
  installed is likely to stop the guest booting.**

- `vgpu_profile` (string) - vGPU profile to attach, matched as a case-insensitive substring
  of the pool's vGPU type names: `t4-2q` selects `GRID T4-2Q`. The build fails, after
  cloning, if no type matches. Defaults to none.

- `vm_other_config` (map of string→string) - Key/value pairs added to the VM's
  `other-config`. Defaults to empty. Two keys are reserved; see
  [Build Provenance](#build-provenance).

### Communicator Configuration

Set `communicator = "winrm"`, with `winrm_username` and `winrm_password`, to provision the
guest. The default, `none`, connects to nothing and runs no provisioners.

#### Common

- `communicator` (string) - `none` (the default) or `winrm`.

- `pause_before_connecting` (duration string | ex: "1h5m2s") - How long to wait, once
  WinRM is reachable, before provisioning starts. Use it when WinRM comes up before the
  guest has finished its own setup. Defaults to no pause.

#### Windows Remote Management (WinRM)

Packer must be able to reach the VM on its network. With `winrm_use_ssl = true`, the
source's 5986 listener must present a certificate that the machine running Packer trusts,
issued for the address Packer connects to; leave `winrm_insecure` at its default, `false`,
so that Packer verifies it.

@include 'xenserver/common/WinRMConfig.mdx'

Set `winrm_host` for a guest reachable only through NAT or a jump address. The build still
waits for the guest to report an address first.

@include 'xenserver/common/GuestCredentialsEnv.mdx'

### Output and Retention

- `format` (string) - What the build produces:

  | Value            | Result                                                                    |
  | ---------------- | ------------------------------------------------------------------------- |
  | `xva`            | A gzip-compressed XVA file, `<vm_name>.xva`. The default.                 |
  | `xva_compressed` | Deprecated alias of `xva`.                                                |
  | `vdi_raw`        | One raw image per disk, `<vdi-uuid>.raw`.                                 |
  | `vdi_vhd`        | One VHD image per disk, `<vdi-uuid>.vhd`. Disks over 2040 GiB cannot be exported this way. |
  | `none`           | No file: the finished VM is converted to a template and left on the pool. |

- `output_directory` (string) - Directory for the exported files. Defaults to
  `output-BUILDNAME`. It must be missing or empty; `packer build -force` empties it first.
  `-force` also destroys any VM or template on the pool named `vm_name`, with its disks.

- `keep_vm` (string) - When to keep the VM on the pool: `never`, `always` or
  `on_success`. Defaults to `on_success` with `format = "none"`, and to `never` otherwise;
  `never` with `format = "none"` is rejected. Use `always` to keep the VM of a failed build
  for debugging.

- `create_snapshot` (bool) - Snapshot the VM after it shuts down, before it is exported.
  Defaults to `false`. The build never deletes the snapshot, even with
  `keep_vm = "never"`.

- `snapshot_name` (string) - Name label of that snapshot. Only valid with
  `create_snapshot = true`.

- `install_timeout` (string) - How long to wait for the guest to report an address to
  connect to over WinRM. Defaults to `200m`.

- `shutdown_command` (string) - Command run inside the guest over WinRM to shut it down
  after provisioning; it needs `communicator = "winrm"`. Without it, the VM is shut down
  through the XenAPI. If the VM has not halted within five minutes, it is powered off.

## Troubleshooting

- **The build waits for the guest and fails with no IP address** — the address comes from
  the XenServer VM Tools, so install them in the source, or set `communicator = "none"` if
  the build does not need to provision the guest.

- **An error about `firmware` and the source's boot mode or vTPM** — remove `firmware` to
  keep the source's own, or clone a source that boots the way you need. `vtpm = false` also
  clears the vTPM case, at the cost of the vTPM's contents (see `vtpm`).

- **`ca_cert_path must be specified when insecure is false`** — export the pool's
  certificate with `xe host-get-server-certificate host=<host-uuid> > pool-ca.pem` and
  point `ca_cert_path` (or `XENSERVER_CA_CERT_PATH`) at it.

- **`certificate is valid for X, not Y`** — connect with a name or address the pool's
  certificate is issued for.

- **`HOST_IS_SLAVE`** — point `xenserver_host` at the pool coordinator (master).

- **`could not find a template named 'X'`, `found 2 VMs named 'X'`, or `... names a
  template, not a VM`** — the name must match exactly one object of the kind the option
  takes: a template for `clone_template`, a VM or snapshot for `clone_vm`. Rename
  duplicates.

- **`clone_vm 'X' is Running, and this build needs a halted source`** — shut the VM down,
  or snapshot it and name the snapshot in `clone_vm`.

- **WinRM never connects** — check that the source's HTTPS listener is up on 5986, the
  firewall allows it, the credentials are right, and the listener's certificate is trusted
  by the machine running Packer and issued for the address Packer connects to.

- **Debugging a failed build** — set `keep_vm = "always"`; `on_success` deletes the VM of
  a failed build.

## Required Privileges (RBAC)

The account in `xenserver_username` needs one of these roles:

| Role              | Suitable for this builder?                                   |
| ----------------- | ------------------------------------------------------------ |
| Pool Admin        | Yes — more than required.                                    |
| **Pool Operator** | **Yes — recommended.**                                       |
| VM Power Admin    | Yes.                                                         |
| VM Admin          | No — it cannot set the VM's memory, which `vm_memory_gb` needs. |
| VM Operator       | No — it cannot clone VMs.                                    |
| Read Only         | No.                                                          |

See [RBAC roles and permissions](https://docs.xenserver.com/en-us/xenserver/9/users/rbac-roles-permissions.html).
