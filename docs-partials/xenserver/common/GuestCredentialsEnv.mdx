#### Supplying guest credentials from the environment

The guest login falls back to these environment variables when the template does not set
it; a value in the template wins.

| Option                 | Environment variable             |
| ---------------------- | -------------------------------- |
| `winrm_username`       | `XENSERVER_WINRM_USERNAME`       |
| `winrm_password`       | `XENSERVER_WINRM_PASSWORD`       |

~> **Do not hardcode guest credentials.** A password in a `.pkr.hcl` or `.pkrvars.hcl`
file is committed with it. Supply it from the environment instead.

```shell-session
$ export XENSERVER_WINRM_USERNAME=Administrator
$ export XENSERVER_WINRM_PASSWORD=...
$ packer build .
```
